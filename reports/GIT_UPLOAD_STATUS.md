# GitHub 통합 및 업로드 상태

## 사용자 선택

사용자가 **CSV 이력까지 전송하지 말고 push 보류**를 선택했다.
따라서 원격 쓰기와 push를 수행하지 않는다.
기존 커밋을 삭제·재작성하거나 force push하지 않는다.

## 이력 및 파일 비교

- 기존 master: `68e5acc316ac7bedff4732bc025a2dac2cfd5a64`.
- 기존 master 부모: `519bd5e`.
- 캐시된 origin/main: `c82d764f01d97492d8b26c69e25703299a9ed2b0` (Initial commit).
- 공통 조상이 없는 독립 이력. 좌우 고유 커밋 수: 원격 1, 로컬 2.
- 캐시된 원격 트리에는 README.md 1개(9 bytes, `# gripper`)가 있었다.
- README의 add/add 충돌을 원격 내용 + 로컬 개발 문서의 결합으로 해결했다.
- 원격 README 원문을 docs/origin-main-README.md에도 보존했다.
- master는 기존 SHA를 유지하며 main에서 merge한다.

## 업로드 점검

도달 가능한 모든 커밋의 blob 및 중첩 ZIP 내부를 점검했다.
비밀키·AWS/GitHub/Slack 토큰 및 인증정보 대입 패턴, 인증 파일명 검사를 실시했다.
탐지된 인증정보와 추적된 빌드 결과물·캐시·실행 바이너리는 없었다.
이 검사는 알려진 패턴에 대한 탐색이며 모든 형태의 비밀정보 부재를 증명하지 않는다.
10 MiB 초과 blob은 없었다.

1 MiB를 보수적인 실험 CSV 제외 기준으로 정했다.
기존 이력 및 기존 최신 트리에서 1 MiB 초과 CSV가 22개 발견됐다.
이들은 모두 재생성 가능한 timeseries.csv다. 작은 파일 3개를 포함한 전체 시계열 CSV 25개를
인덱스에서만 제거하고 로컬 파일은 남겼다.
요약 CSV, Windows 골든 CSV, 인수인계 원본은 계속 추적한다.
.gitignore에 시계열 출력·인증 파일 제외 규칙을 추가했다.

현재 트리에서 파일을 제외해도 merge 부모의 과거 CSV blob은 이력에 남는다.
기존 커밋을 원격 main의 조상으로 포함하는 push는 그 CSV도 전송한다.
사용자 선택에 따라 이 통합 이력은 push하지 않는다.
과거 CSV까지 원격에서 제외하려면 기존 master를 로컬에 보존하면서
원격 main을 기반으로 파일만 가져오는 별도 스냅샷 이력이 필요하다.
이는 이번 merge와 다른 게시 방식이며 현재 실행하지 않았다.

## 원격 접근 제한

git fetch는 github.com DNS 해석 실패로 종료했다.
연결된 GitHub 앱도 해당 저장소 메타데이터 요청에 404를 반환했다.
따라서 캐시된 origin/main 이후 원격 변경은 확인하지 못했다.
로컬 통합은 캐시된 커밋을 대상으로 하며 원격 상태와 동기화되었다고 주장하지 않는다.

감사 JSON은 해당 검사 시점의 HEAD와 탐색 범위를 기록한다.
최종 커밋 SHA는 git log -1 및 사용자 응답으로 보고한다.
